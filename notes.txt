Stack
-----
Zero-dependency static site: plain HTML + CSS + vanilla JS, hand-rolled SVG
charts. No framework, no build step, no analytics, no wallet connection,
no third-party requests at runtime. Fonts self-hosted (Instrument Serif,
Inter Tight, IBM Plex Mono — SIL OFL). Brand kit colours (ground #12100E,
maroon #3A1420, panel #221E1A, cream #EFE9E2, magenta #E74079 accent).

Endpoints used (base https://api.taskmarket.dev, no key)
--------------------------------------------------------
- /api/market/stats?chainId=4217 and ?chainId=8453
- /api/stats/breakdowns?chainId=4217
- /api/stats/platform-time-series?chainId=4217&range=7d|30d|90d&bucket=day
- /api/stats/platform-time-series?chainId=4217&range=all&bucket=week
- /api/stats/activity-heatmap?chainId=4217&range=30d&dimension=hourOfWeek
- /api/stats/activity-heatmap?chainId=4217&range=30d&dimension=mode
- /api/stats/activity-feed?chainId=4217&limit=50 and ?chainId=8453&limit=50
- /api/tasks?chainId=4217|8453&status=<each of open, completed, cancelled,
  expired, claimed, pending_approval, worker_selected>&sort=newest&limit=100&cursor=…

How and how often it refreshes
-------------------------------
Server-side, every hour: a scheduled job runs `node scripts/fetch-data.mjs`,
which fetches every endpoint above, trims + aggregates the responses, and
writes data/data.json; the job commits + pushes when the file changed, and
GitHub Pages serves the new file within minutes. The page reads only that
static file — the browser never calls api.taskmarket.dev (the API blocks
cross-origin browser requests). The "Data as of" time on the page is the
fetch time; the static file is effectively cached for the hour between
refreshes.

The same refresh is also available as a GitHub Actions workflow
(.github/workflows/refresh.yml, cron '0 * * * *') for self-hosting; its full
YAML is pasted in the README. It is NOT in the repo yet because pushing
.github/workflows/* needs the `workflow` OAuth scope, which the default `gh`
login does not have. To activate it: `gh auth refresh -h github.com -s workflow`
(enter the one-time code at https://github.com/login/device in your browser),
then `git add .github/workflows/refresh.yml && git commit -m "Add hourly refresh workflow" && git push`.
Until then the scheduled job above keeps the data fresh.

Deploy command (one command, works from a clean clone)
------------------------------------------------------
  ./deploy.sh [repo-name]        # default: taskmarket-live

Creates the public repo (or pushes to the existing origin), enables GitHub
Pages from main (root), triggers the first refresh workflow, prints the live
URL. Requires `gh` logged in. Verified from a clean clone in /tmp on
2026-11-25 (exit 0, live URL printed).

What it shows
-------------
Headline numbers (Tempo / Base / both); "Follow the money" flow view
(top posters -> rewards put up -> paid out -> top winners); trends with
metric + range switches; tasks by status/mode/actor; hour-of-week and
mode-by-day heatmaps; distinct posters per week + concentration; the
"swarm" of open tasks as bubbles sized by reward; live activity feed;
five computed insights (concentration 53.4% from 5 posters, 17.6% of
tasks died, median 24h decision window, +134% tasks WoW, peak hour
Fri 04:00 UTC); full methods note naming every endpoint. Deep links:
#flow #trends #breakdown #heatmap #posters #swarm #feed #insights #methods.
